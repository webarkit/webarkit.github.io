    addEventListener

    • addEventListener(name: string, callback: NFTEventListener): void

      Add an event listener on this ARControllerNFT for the named event, calling the callback function whenever that event is dispatched. Possible events are:

      • getNFTMarker - dispatched by process() for every NFT marker found in the frame
      • lostNFTMarker - dispatched by process() once a tracked NFT marker has been out of view for longer than the lost threshold (a single missed frame is not a loss)
      • load - dispatched when the ARControllerNFT is ready to use (useful if passing in a camera URL in the constructor)

      Listeners are kept in an array, not a set: registering the same callback twice makes it fire twice per event, and each removeEventListener() call drops one registration.

      Parameters

      • name: string

        Name of the event to listen to.

      • callback: NFTEventListener

        Callback function to call when an event with the given name is dispatched.

    configure

    • configure(patch: NFTRuntimeSettingsPatch): void

      Changes several runtime settings at once (#720): the planes, the detection policy, filtering, the log level and the AR2 tracking parameters. The patch is deep-merged into getRuntimeSettings (ar2 field by field) and applied in one native call, which validates everything first and changes nothing on failure. getCameraMatrix() reflects new planes at once.

      logLevel is per controller: the level lives in the WASM module's globals, and each controller's init() creates its own module. The core takes 0..4 (or -1 for "leave it"), so a level above 4 is refused with a RangeError, except the controller's current level: that counts as no change, so a getRuntimeSettings() round trip succeeds at any level, a silenced one included. Set a level above 4 with setLogLevel() or the init option.

      Parameters

      • patch: NFTRuntimeSettingsPatch

        any subset of the settings.

      Returns void

      Example

      ar.configure({ near: 1, far: 5000, ar2: { simThresh: 0.6 } });

      Throws

      on an unknown key (including the deprecated square-marker keys threshold, thresholdMode, imageProcMode, debugMode), a value of the wrong type, or a non-integer for an integer field (logLevel, ar2.searchFeatureNum, ar2.templateSize1/2, ar2.searchSize); nothing is changed.

      Throws

      when the values are out of range; nothing is changed.

    loadNFTMarker

    • loadNFTMarker(
          url: string | string[],
          onSuccess?: (id: number) => void,
          onError?: (code: number) => void,
          opts?: NFTLoadOptions,
      ): Promise<number[]>

      Loads one NFT marker and resolves once it is registered, so tracking can start right after the await.

      Promise style (preferred): it rejects with an NFTLoadError, whose kind tells a missing file ("http") from a bad one ("format"), or with the abort reason when opts.signal fires.

      try {
        const [id] = await arController.loadNFTMarker("path/to/marker");
      } catch (err) {
        if (err.kind === "http") console.error("Not found:", err.url, err.status);
      }

      Callback style (deprecated, kept for existing callers): it never rejects for a load failure; the failure goes to onError, or to console.error when there is no onError, and the Promise resolves [].

      arController.loadNFTMarker("path/to/marker", (id) => {
        console.log("Marker loaded with ID:", id);
      }, (code) => {
        console.error("Failed to load marker:", code);
      });

      Parameters

      • url: string | string[]

        The marker's base URL, or the list of its file URLs.

      • OptionalonSuccess: (id: number) => void

        Deprecated. Called with the marker ID.

      • OptionalonError: (code: number) => void

        Deprecated. Called with the HTTP status, or -1.

      • Optionalopts: NFTLoadOptions

        Loading options, such as an abort signal.

      Returns Promise<number[]>

      A Promise that resolves to [id].

    setContinuousDetection

    • setContinuousDetection(enabled: boolean): void

      Turn continuous detection on or off.

      Detection (KPM) is the expensive step that finds a marker which is not yet tracked; a pass costs the full detection time on the frame where it runs, far more than tracking an already-found marker. The policy is:

      • while no marker is tracked, detection runs on every frame;
      • while at least one marker is tracked and at least one loaded marker is not, detection runs at most once per detection interval (see setDetectionInterval), so a marker that enters the view is still picked up;
      • while every loaded marker is tracked, detection does not run.

      With continuous detection off, no detection runs once any marker is tracked, until tracking is lost: the single-marker behaviour of 1.12.0. That is cheapest, but a second marker entering the view is not found while the first one is held.

      Parameters

      • enabled: boolean

        Default true.

      Returns void

      Inherited from ARControllerNFTBase.setContinuousDetection

    setDetectionInterval

    • setDetectionInterval(ms: number): void

      Set the minimum time from the end of one detection pass to the start of the next, while at least one marker is tracked and at least one is not (see setContinuousDetection).

      Detection is measured in time, not frames. A longer interval spends less time detecting, at the cost of noticing a newly visible marker later; 0 detects on every frame, which costs the full detection time on every frame while any loaded marker is out of view.

      Parameters

      • ms: number

        Milliseconds. 0 means every frame; negative values are treated as 0. Default: 300.
